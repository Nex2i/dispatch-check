# Implement the selected MVP

Before implementation, complete the ideation billing TODO in `docs/pipeline.md` and the billing section in `requirements/mvp.md`. Select subscription, credits, pay per use, one-time purchase, or a justified hybrid according to buyer value and delivery economics. Record pricing assumptions, billable units, free limits, entitlements, settlement timing, cancellation/refund/failure rules, authoritative records, and acceptance tests. Implement the selected model rather than automatically using subscriptions.

Read `requirements/idea.json`, `requirements/mvp.md`, `requirements/template-requirements.md`, and `AGENTS.md`. Read `docs/mvp-runbook.md`. Read the opportunity report supplied for this run and `docs/pipeline.md`. Select the opportunity and complete its requirement brief autonomously; do not ask the founder to approve the idea, requirements, routine implementation choices, or configured deployment. Record those decisions for the post-deployment handoff. Do not infer that a project should be built from a research score alone; use its explicit decision level and current buyer evidence.

If `idea.json` is still in template status, first turn the selected experiment into a concrete, reviewable requirement brief. Resolve buyer, trigger, accepted output, and measurable acceptance criteria from the research evidence, recording unvalidated choices as assumptions. If the evidence cannot support a concrete experiment, report the specific unresolved gate instead of inventing customer validation.

Build the smallest complete buyer task in the existing React/API/Postgres app. Keep the landing page claim specific and label unverified claims as hypotheses. Implement reusable authentication according to `docs/auth-design.md` as part of the required customer-ready deliverable. Use environment secrets, migrations, safe logs, and deterministic tests. Never commit customer data or credentials.

Run `npm test` and `npm run build`. Review the diff, list unmet requirements and operational risks, and deploy only after the fixed Netlify/Render deployment profile and actual CI gate is configured. For a customer-facing deployment, verify registration, email confirmation, username login, reset, logout, session behavior, and the core buyer task. Prefer MCP and CLI checks; provide the founder with browser steps for interactions that were not exercised automatically, and label them unverified. Record actual URLs and results in `requirements/mvp.md`. Finish with the selection rationale, assumptions, changes, repo and deployed links, test evidence, open issues, and a manual test checklist with expected outcomes. Distinguish implemented, automatically verified, and awaiting manual review.

Every run targets a customer-ready MVP and SEO-led organic discovery with no ads. Implement the SEO brief in the first build and verify crawler-visible HTML, hydration, canonical metadata, sitemap/robots, real404s, hostname redirects, mobile/performance and Search Console status. Never substitute a disposable anonymous demo for the requested deliverable. Use the runbook's early access check, secret-handling rules, exact-session payment tests/cleanup and single verification ledger. Missing access, ownership or durable-resource budget leaves a documented blocker; it does not waive release requirements.
