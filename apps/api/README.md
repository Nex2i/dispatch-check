# Dispatch Check API

Default review mode (`CUSTOMER_RELEASE_ENABLED` absent/false) requires no credentials. `/health` returns healthy review status; `/api/status` returns `{mode:"review",customerReleaseEnabled:false}`. Every other `/api/*` returns503 before body parsing: no account/payment/customer inputs accepted. Deploying this mode does not make customer accounts or paid exports available.

Customer mode remains release-blocked. It requires isolated nonexpiring PostgreSQL/backup capacity, `DURABLE_DATABASE_CONFIRMED=true`, exact HTTPS APP_ORIGIN, an isolated 32+-character auth secret, verified Resend sender/support mailbox, an isolated Stripe sandbox test key, and webhook signing secret. Live keys and live events fail closed. Runtime cannot infer backup readiness from an environment variable: the flag records an external verified gate, not proof by itself. Run `npm run migrate --workspace @nex2i/api` before startup: Better Auth validates its schema on initialization. Build with npm ci --include=dev and npm run build --workspace @nex2i/api; start with npm start --workspace @nex2i/api. Database SSL validates certificates when enabled. Use Netlify same-origin `/api/*` proxy and host-only secure cookies. Proxy IP trust remains disabled until a real trusted ingress boundary is verified (conservative IP limit behind proxies, plus independent identity limits).

Better Auth1.7.7 implements verified signup, username/email login, recovery, logout and immediate session revocation. Password reset requires frontend `/reset-password/` and expires after30min; resetting revokes every session. Browser mutations require exact Origin. Deletion requires current password; pending open Checkout sessions expire before user deletion. User deletion cascades local orders/auth records. Stripe retains provider financial records under its own retention; deletion does not initiate a refund. `/api/account/export` returns profile and this account's order status/dates, excludes auth/payment tokens. Local analysis stays in-browser. Paid packet generation sends an explicitly consented, fixed-schema pseudonymous schedule to /api/report for transient processing; no CSV/report is stored.

`GET /api/entitlement` requires verified cookie; returns `{active,expiresAt,canExport,maxRows}` (25 free,2000 paid). Active passes recheck current Stripe session/intent/latest-charge state, so missing/reordered refund/dispute events cannot preserve stale paid access. Provider failures return503 and grant nothing. `POST /api/checkout` takes `{}` (client prices ignored), requires exact Origin and verified cookie, returns `{url}`. Active repurchase returns409; open pending Checkout is reused; completed pending payment returns409 until signed fulfillment. Checkout fixes$19USD, mode payment, dynamic methods and random-suffixed integration identifier. Never grant from return query parameters.

`POST /api/billing/webhook` requires the original unmodified JSON bytes and valid Stripe signature (no browser Origin requirement). Subscribe to checkout.session.completed, checkout.session.async_payment_succeeded, checkout.session.async_payment_failed, checkout.session.expired, charge.refunded and charge.dispute.created/updated/closed. Current Checkout/payment/charge objects are retrieved before reconciliation, not taken from stale event payload. Existing locally initiated session/order/owner must match. Unique session/intent/event constraints, advisory owner lock and transactions prevent duplicate grants. Payment status must be paid and PaymentIntent succeeded; amount1900USD and sandbox mode checked. Pass expires30days after authoritative charge creation. Full refunds or any dispute revoke the pass; revocation is terminal even if a stale paid event arrives or a dispute is later won (support must decide a new pass). Partial refunds do not revoke by the specified full-refund policy. No renewal or live commerce implemented/authorized.

Safe logs contain lifecycle event/status/generated request ID/HMAC pseudonym only. Automatic raw request logging and raw error serialization disabled; no token-bearing URLs, cookie, credentials, addresses, raw provider responses or CSVs logged. Atomic PostgreSQL per-email/username limits complement persisted Better Auth IP limits. API replies noindex/no-store/no-referrer/frame-ancestors none. Use a separate frontend synthetic portfolio preview.

Local evidence: build passed;11 API tests passed against isolated local PostgreSQL with no skips on October4,2026. Billing fixtures test unpaid/paid/expiry/refund/dispute/fixed-price/live rejection, signature tampering, actual PostgreSQL transactional replay/ownership/rollback/deletion cascade, and review fail-closed behavior. Set TEST_DATABASE_URL to a throwaway PostgreSQL admin URL (CREATE/DROP DATABASE permission required) to rerun; ordinary npm test skips2 database tests if unset. Provider fixtures are not actual Stripe/Resend interactions. Dedicated sandbox ownership/expiry, browser payment/refund/session linkage, real email/bounce monitoring, deployed API, trusted proxy, durable backup/restore and operations monitoring remain pending. `POST /api/report` accepts JSON `{csv,dailyCapacityHours,consent:true}` only with a verified account, active provider-reconciled pass and exact Origin. The raw JSON body and CSV are bounded to2MiB; analysis is capped at2000jobs/10000issues. It returns `{issuesCsv,jobsCsv,summary}` from the server, neutralizes formula cells, and refuses structurally incomplete reviews with422. Missing/expired/free pass returns402, unauthorized401, omitted consent400. Fixed headers exclude names/addresses; IDs must be bounded pseudonyms. The frontend must never generate customer paid packets locally from client-only entitlement flags. Source-equality regression keeps copied API/web domain checker code identical; source changes require copying both.
